# Radio controls and telemetry inventory

The two directions have different purposes. TX16S -> ER8 -> FC carries pilot commands. FC -> ER8 -> TX16S carries flight telemetry. Receiver link statistics are generated by ExpressLRS itself. This update removes none of the existing flight telemetry groups.

## TX16S to ER8 to flight controller

| Channel | Assignment | MANUAL | ASSIST | TKOFF |
|---|---|---|---|---|
| CH1 | Aileron / roll | Direct aileron | Bank target, +/-40 deg | Bank target, +/-10 deg |
| CH2 | Elevator / pitch | Direct elevator | Pitch target, +/-26 deg with configured trim | Direct elevator |
| CH3 | Throttle | Pilot throttle, subject to arming/failsafe | Same | Same |
| CH4 | Rudder / yaw | Direct rudder | Direct pilot rudder plus bounded yaw damping; full stick overrides damping | Direct rudder |
| CH5 | Arm switch | Low = disarm; deliberate high transition at idle = initial arm | Same | Same |
| CH6 | Spare | Ignored | Ignored | Ignored |
| CH7 | Mode switch | Low requests MANUAL | Middle requests ASSIST | High requests TKOFF |
| CH8 | Spare | Ignored | Ignored | Ignored |
| CH9-16 | Unassigned | Parsed when present in full CRSF channel packets; not used by control | Same | Same |

Use AETR order and the actual received channel monitor described in [TX16S_SETUP.md](TX16S_SETUP.md). A 100 Hz RF profile does not imply a new independent sample for every auxiliary channel at 100 Hz; switch mode and telemetry slots matter. The FC processes channels at 400 Hz but can only use new commands as they arrive. The ER8 serial connection is UART4/J2 at 420000 baud, 8N1.

An unused channel is not a removable custom telemetry field. ELRS/CRSF channel packing is defined by the selected radio mode. Removing CH6 from our application would not shorten its normal CRSF RC packet. CH5 and CH7 remain necessary for the agreed controls.

No in-flight PID tuning, parameter upload, waypoint upload, calibration command, automatic launch command or ground-station command protocol is implemented over this link. ELRS binding/configuration traffic belongs to the radio system and is not an FC command interface.

## Flight controller to ER8 to TX16S

| CRSF group/type | Fields currently sent | Configured maximum generation rate | Notes |
|---|---|---|---|
| Attitude `0x1E` | Pitch, roll, relative yaw | 10 Hz / 100 ms | Radians on the wire. Yaw has no compass reference and can drift. One compound frame. |
| Vario `0x07` | Vertical speed | 10 Hz / 100 ms | m/s, positive up; barometer-derived and filtered. |
| GPS `0x02` | Latitude, longitude, groundspeed, course over ground, MSL altitude, satellite count | At most 2.5 Hz / 400 ms; new timed GGA fixes only | Six fields in one compound frame. Course is not nose heading; groundspeed is not airspeed. Zero speed/course can mean unavailable RMC data. |
| Flight mode `0x21` | Mode/arming/development/fault text | 2.5 Hz / 400 ms periodically; changes prioritized, at most 10 Hz | Labels below. Actual delivery remains limited by the RF link. |

The scheduler runs at 100 Hz but sends at most one whole CRSF frame per invocation. It uses the latest sensor values, counts UART queue failures, and reserves each eligible group's turn so small frames cannot starve GPS. A token budget limits emitted **CRSF bytes** to a configurable rate, with at most 32 bytes of initial/reconnect credit. Defaults keep every group enabled, preserve the earlier target rates, and use a 240 B/s budget. This is not an automatic measurement of ELRS air bandwidth. Set it using the actual packet format/version/rate/ratio and reception tests; overhead and RF fragmentation reduce useful capacity.

Configuration lives in `src/config/airframe.hpp`, `config::telemetry`. Array order is **attitude, vario, GPS, mode**. Each group has an enable flag and minimum interval. For example, disabling `enabled[0]` removes the complete attitude frame. Standard CRSF does not provide a smaller attitude packet just because we omit yaw from the screen.

USB `TELEM,a,v,g,m,deferred,queue_failures` reports the number of queued frames by type and scheduling diagnostics. These counters are not acknowledgements from the handset. A radio-side capture or time-stamped Lua widget is required to measure end-to-end refresh/age. The FC has no receiver acknowledgment for each displayed sensor value.

### Mode text

- `MANUAL`, `ASSIST`, `TKOFF`: motor-authorized mode.
- A trailing `*`: disarmed mode.
- `B-MANUAL`, `B-ASSIST`, `B-TKOFF`: development build with motors inhibited.
- `!FS-LVL`: RC failsafe, healthy eligible attitude; throttle cut and leveling requested.
- `!FS-CTR`: RC failsafe without eligible stabilization; throttle cut and surfaces centered.
- `!LOCK`: stabilization fault lockout.
- `!TIMING`: latched control deadline fault.

These strings do not automatically create spoken EdgeTX alarms. Configure alarms independently. No FC message can be guaranteed to arrive through a lost RF link.

## ELRS-generated link information

Our CRSF parser recognizes the standard link-statistics structure: uplink RSSI antenna 1 and 2, uplink link quality, uplink SNR, active antenna, RF mode, transmitter-power enumeration, downlink RSSI, downlink link quality and downlink SNR. The radio/receiver firmware determines availability and how EdgeTX exposes these values. They are not ten additional FC-scheduled telemetry messages, and disabling our attitude/GPS groups does not disable ELRS link statistics.

## Data not currently sent over the radio

No battery voltage/current/consumed mAh/remaining percentage is scheduled. A battery-frame encoder exists but has no validated measurements feeding it. No raw gyro/accelerometer, second-IMU streams, magnetometer axes, pressure, temperature, SD records, individual servo positions, PID terms, USB debug text or scheduler timings are sent over ELRS. Those diagnostics stay on USB/SD. There is no MAVLink/QGroundControl link.

## Deciding what to reduce later

Keep control channels CH1-5 and CH7. For return telemetry, mode/fault state and ELRS link quality are useful first priorities. Keep GPS if recovery/location and ground-track information matter. Vario can be reduced or disabled if climb/descent indications are unused. Attitude is the first candidate to reduce if no artificial-horizon widget is used; its yaw is currently relative. No reductions have been applied yet.

References: [ExpressLRS Lua packet-rate/telemetry settings](https://www.expresslrs.org/quick-start/transmitters/lua-howto/), [telemetry bandwidth](https://www.expresslrs.org/info/telem-bandwidth/), [switch/channel modes](https://www.expresslrs.org/software/switch-config/). Air telemetry opportunities are shared between link and data traffic; they are not individual sensor update rates.
